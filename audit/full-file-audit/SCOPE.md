## 3. Explicit Scope Exclusions with Justification

The following directory trees, disposable caches, and untracked binaries are excluded from the file ledger:

1. **`.git/`**  
   *Justification:* Internal Git version control database and object store metadata.
2. **`node_modules/`**  
   *Justification:* Ephemeral third-party npm package dependencies. Audited collectively via `package-lock.json`, `package.json`, and `npm audit` rather than individual vendor source review.
3. **`pawwork/`**  
   *Justification:* Independent, untracked submodule/clone of an external frontend application with its own `.git` directory, not committed to the GravityClaw repository.
4. **`pawwork-win-x64.exe`**  
   *Justification:* Untracked 210MB standalone binary artifact present in workspace root, not tracked in Git.
5. **Runtime Artifacts and Transient Caches:**  
   - `dist/` (build output from `esbuild`)
   - `coverage/` (test coverage reports)
   - `.kilo/` (local editor telemetry cache)
   - `logs/` (local server execution logs)
   - `data/` and `gravity.db*` (local runtime SQLite databases)
   - `backups/` (runtime local database snapshots)
   - `memory-files/` (runtime memory dumps)
   - `audit/full-file-audit/` (output artifacts generated by this audit)

## 4. Methodological Standards

1. **Rule 1: The README is Not Proof** — Every functional, architectural, and security claim in documentation was cross-referenced against the actual implementation.
2. **Rule 2: Every File Individually Accounted For** — Exactly 773 structured records exist in `FILE_LEDGER.jsonl`.
3. **Rule 3: Implementation is the Source of Truth** — Code takes precedence over comments, claims, specs, and prior reports.
4. **Rule 4: Absolute Disclosure** — No file was silently skipped; all findings link to specific code lines and affected files.
